# Pyramid Proの4ch LEDメーターと背景取得ボタン案

2026-11-18。提案段階。Pyramid 0.2.3でブラウザからC5を使う手順と復旧先は[配備・実機検証](jet-waterfalls.md)を参照。

## 実機と公式資料で確認したこと

- Pyramid ProはRGB LEDを48個搭載。対象実機で `ec_proxy.service` が稼働し、`ec_cli device --rgb_size` は48、`ec_cli device --rgb` はモード1、`ec_cli device --version` は1を返した。
- 実機のCLIは `rgb_set_color` / `rgb_get_color` と `ec_cli echo --button` を公開している。公式の個別LED制御はモード0。1コマンドは1個を指定するため、更新レートは実測で決める。
- 上部ボタンの短押しには工場出荷時の音声アシスタント操作があり、長時間の長押しには強制電源OFFがある。実機では音声関連サービスも稼働していた。どの押下・解放がどのイベントになるか、既存機能がどう反応するかは未実測。
- 4本のバーとLEDインデックスの対応、バー内の始端と終端、実際の発光、LEDを更新した場合のC5の欠落率は未確認。

参照：[Pyramid Proの仕様](https://docs.m5stack.com/en/ai_hardware/AI_Pyramid-Pro)、[EC Proxy制御](https://docs.m5stack.com/en/compute/ai_pyramid/ec_proxy)、[上部ボタンの工場出荷時動作](https://docs.m5stack.com/en/compute/ai_pyramid/getting_started)、[EC Proxyソース](https://github.com/m5stack/AI-Pyramid-EC-Proxy)。

## LEDメーターの初版

物理バー1本をWebの1枠へ対応させ、色を各枠と揃える。初期の対応はE2・E1・F3・F5で、Webで選び直したら枠のチャンネルに追従する。端から連続して光らせ、受信が強いほど点灯数を増やす。

点灯数の入力は `Monitor.monitor_loop()` が100msごとに集計する `levels` の receiver dB。4ch監視の `live`・`fresh` 条件に限定し、欠測した枠は消灯する。帯域走査、RH計測、背景取得中は信号バーを休止する。表示範囲は全枠共通の固定値から始め、現場の弱い信号も見えるよう実測で調整する。各枠の自動スケールで比較条件を変えない。

受信スレッド外で最新の表示状態だけを消費する。低輝度・低頻度で始め、前回から変わったLEDだけをEC Proxyへ送る。許可したLEDインデックスとRGB値だけを渡し、ECのシリアルポートは既存のProxyが所有する。操作は初期OFFのオプションにし、有効化の前に現在のRGBモードを読み、解除時の復元を確認する。音声アシスタントが同じLEDを使う場合の優先順位は実機で確認する。

## 上部ボタンで背景を取得する案

LEDを先に検証し、その後にボタンを追加する。まず `ec_cli echo --button` で短押しを観測し、押下と解放の対応、重複、音声アシスタントとの競合を確認する。工場機能と両立できる押し方が確認できたら、1回目で確認待ちに入り、全VTXがOFFであることを人が確認してから、猶予時間内の2回目で取得を開始する。段階はWebや通知用の点灯で示し、時間切れと記録中は要求を取り消す。

既存の `Monitor.request()` と `background_loop()` を使う。背景は詳細走査5回から保存され、通常の4ch監視は取得中だけ中断する。全VTX OFFの明示確認、記録中・終了処理中・通過計測中の拒否、取得の成否を表示する。失敗時には以前の背景を使用できる状態で残す。物理イベントからそのまま `allOffConfirmed` を成立させるのは、確認操作が成立した場合に限る。

4chメーターを背景からの差でゼロ合わせする場合は別段階。既存の背景は広域走査用なので、同じ4chプロファイルで取得したチャンネル別の無送信基準を使う。RAW受信値、WFの背景差、RHの通過しきい値とは用途を分ける。

## 別PCでの着手順

1. [引き継ぎ](handoff.md)に従ってPyramid実機の版、C5個体、`/api/state` の受信と記録状態を確認する。
2. 記録していない時間帯に、LEDを低輝度で1個ずつ短く点灯させるテストで各バーのインデックスと向きを記録し、元のRGBモードへの復元を確認する。
3. LEDメーター有効/無効でフレーム数・欠番・C5 drops・CPUを比較する。1台だけON/OFFして、該当バーの長さが受信値に追従するか確認する。
4. ボタンイベントと工場機能の競合を確認し、物理操作の確認待ち・VTX全機OFF・記録保護・背景保存を試す。競合が解決するまでは既存Webの背景取得を使う。

今回の実機調査は読み取りのみ。LEDメーター・ボタンのコードと配備は未着手。個体情報や接続設定はローカルへ置く。
