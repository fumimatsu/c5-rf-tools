# Tab5 C5 RF Monitor — 0.6.0

XIAO ESP32-C5 / C5MKをTab5のUSB-Aで読み、5.8GHzの選択した4chと広域を調べる表示アプリ。初期設定はE2・E1・F3・F5。受信電力を見るもので、アナログ/HDZeroの方式識別や映像復調は行わない。

初期4ch（色は枠に固定され、選択したチャンネル名と周波数が変わる）:

| CH | MHz | 識別色 |
|---|---:|---|
| E2 | 5685 | 青 |
| E1 | 5705 | 緑 |
| F3 | 5780 | 黄土 |
| F5 | 5820 | 赤 |

画面は直角・白灰の計測器風。色は枠の見出し、登録周波数のガイド、履歴の線に使う。濃淡は受信電力で、枠の色は実際の送信元を識別した結果ではない。

0.6.0は720×1280の縦画面。4chカードは2×2、下に履歴、帯域画面には縦長のWFを置く。明るさ調整を追加し、90度のソフト回転と回転用バッファを使わない。[仕様・検証・戻し方](docs/rf4-0.6.0-verification.md)。0.5.1の通信品質・評価窓の修正は維持する。[0.5.1検証](docs/rf4-0.5.1-verification.md)。

## 接続

PC USB → Tab5 USB-C（給電・書き込み・ログ）。Tab5 USB-A → USBデータケーブル → XIAO ESP32-C5 USB-C。

起動時はLCD初期化中にUSB-A給電を切り、1秒待って画面を開始し、250ms後にC5へ給電する。明るさは毎回10%で起動する。電圧/電流は未測定で、10%はTab5の恒久的な上限ではない。

## 操作

### 画面の明るさ

上部の **明るさ** から5〜100%を選ぶ。±5%と5/10/25/50/75/100%のボタンがある。白い「明るさ確認」の帯で変化を比較できる。%はPWM設定値で、測定した光量ではない。設定は保存せず、再起動時は10%へ戻す。高輝度で給電不足による再起動が起きても、その設定で起動を繰り返さないため。現在のPC給電条件では5→10%だけ目視確認し、高輝度は実機検証していない。十分な給電を用意した場所で段階的に確認する。

縦版も画素数は横版と同じ。回転の負荷は外れるが、C5の掃引時間や24掃引のWF履歴数は変わらない。速度改善量は未計測。

### 4枠のチャンネル選択

4ch画面の各枠の見出し、または帯域/WF画面上部の4つの色付きチャンネルボタンを押す。

1. R / A / B / E / F のバンドを選ぶ。
2. 表示されたチャンネル名とMHzを確認して選ぶ。選んだ枠だけ変更し、本体NVSへ保存する。
3. 下部の **セット E2 / E1 / F3 / F5** と **セット R2 / R3 / R4 / R5** は4枠をまとめて変更する。

38チャンネルを選べる。E7=5925MHz、E8=5945MHzは現アプリの走査・背景・マーカーの範囲5645–5917MHz外なので灰色・選択不可。Lowbandは今回含めない。この制限は現アプリの測定範囲によるもので、C5ハードの絶対限界と断定していない。

選択は再起動後も復元し、色は枠に固定。R7とF8のような同じ周波数でも選んだ名前を保持する。各枠で同じチャンネルを選ぶことも可能。これは複数送信元の分離を意味しない。受信側だけを設定し、VTX本体の送信チャンネルは変更しない。

変更時は4ch履歴、ピーク、WF、広域の古い値を消去し、C5の周波数リストを再確認する。4ch画面なら4chへ戻り、WF画面なら設定確認後に走査へ戻る。背景記録中はチャンネル選択を無効にする。

保存背景は残すが未採用へ戻す。**現在の4枠の周波数と順序が一致する背景だけ採用できる**。異なる4chへ変えたら全VTX OFFで再記録する。元の4chへ戻した場合は、設置条件も同じなら以前の保存背景を明示的に採用できる。保存失敗時は設定を変更せずエラーを表示する。

### レベル・安定性と正常基準

4ch画面の各枠に **レベル** と **安定性** を緑・黄・赤・灰、理由付きで表示する。緑は「記録した条件に対して基準内」という暫定評価で、無干渉・映像品質・VTX正常の保証ではない。

各枠の **正常基準** ボタンから、正常な機体を1台ずつ記録する。背景記録とは別の保存データ。

1. 各機とTab5の位置・向き・アンテナ・送信出力を固定する。
2. 全VTXをOFFにし、**全機OFFで無送信を記録（3秒）**。
3. 案内が出たら対象chの正常な1台だけONにし、安定した状態で **対象1台ONで正常基準を記録（10秒）**。
4. 成功すると本体に保存し、4ch画面へ戻る。対象機をONのまま、評価用の10秒分のデータが揃うのを待つ。
5. 別のchも同じ手順で記録し、全台ONで比較する。意図的にOFFにするchは **予定OFF** にすると健康判定を停止する。

無送信時のP95より正常時中央値が10dB以上高く、正常時のP90–P10幅が3dB以下、中央値から6dB超の落ち込みがないことを記録条件とする。暫定的な基準記録の条件で、映像受信に必要なSNRの規格値ではない。無信号・不安定・飽和・欠測・保存失敗は採用せず、以前の保存基準を保持する。

レベルは直近1秒の中央値を正常時中央値と比較する。正常時から6dB以上の低下で黄、12dB以上で赤。無送信P95との差が10dB未満でも黄、6dB未満で赤。大きい受信値だけでは異常としない。

安定性は直近10秒の100ms枠の電力平均から計算する。変動幅、落ち込み回数、連続時間を使う。詳しい暫定式・試験・限界は[正常基準と判定](docs/signal-health.md)。低下が一定なら「レベル赤・安定性緑」になり得る。欠測・飽和・中断は赤へ換算せず灰色、欠測後は評価窓を取り直す。

正常基準は周波数別に本体保存する。同じ周波数には1つの正常基準で、別機体を同じchで使う場合は記録し直す。別名のR7/F8は同じ周波数の基準を共有する。同周波数を複数枠に登録した場合は、健康判定は灰色にする。

再起動・C5再接続後は正常基準を自動採用しない。**正常基準 → 同じ機体・設置・出力：保存正常基準を使う**。C5個体・ファーム・測定設定と周波数を照合する。チャンネル変更後の枠も未採用に戻し、古い履歴で判定しない。

WF中は4chの健康判定を中断し、灰色にする。4ch監視へ戻ると約10秒の評価待ち。現在の方式は他機の電波と目的信号を分離しないため、混信で合計受信値が上がると、目的信号の弱さを隠す場合がある。100ms未満の落ち込みの検出は保証しない。

### 監視・グラフ

- **帯域 / WF**（初期画面）: 5645–5917MHzを走査。上部の **高速 4MHz / 詳細へ** と **詳細 2MHz / 高速へ** で切替。高速は69点、詳細は137点。起動時は高速、選択は電源OFFで高速に戻る。刻み変更時は途中の掃引・WF・広域ピーク・各点の古い値を消し、左端から取り直す。4chの履歴と背景保存は消さない。白点は実際の取得点、線は点の接続。破線は取得点内のraw最大値のピーク保持、灰は採用中の背景。周波数位置をタッチするとRAW・背景差・PK・データ年齢を表示。
- **表示:受信値 / 表示:背景差**: 背景採用中だけ切り替えられる。初期値は受信値で、背景に元から存在した電波も見える。受信値は未校正receiver dBで、dBmではない。
- **ウォーターフォール**: 1行=1回の完了掃引、最大24行。最新が下。濃淡で受信量を表示し、無効点を斜線で区別する。1行を同時測定したものではなく、行間隔も不定なので最古のデータ年齢と実掃引時間を併記する。
- **4ch履歴**: 選択した4chを直接・順番に観測。4カードと60秒履歴。線は100ms枠のraw線形平均電力、点は枠内ピーク。背景採用時は現在の背景との差。カードの大きい数値はFILT（C5平滑値）、RAWとPKは別表示。単位欄と履歴タイトルでも区別する。
- **予定ON / 予定OFF**: 4chカードで変更。背景採用中、予定OFFのchに基準を超える受信上昇が続いた場合に注意する。混信確定・故障判定ではない。広域走査中は4ch連続監視を中断し、カードをLIVEに見せない。
- **IMD候補**: 予定ONの中心周波数から計算した2波/3波の3次候補を表示。発生したことを示す実測マークではない。
- **ピーク消去**: 保持した4chと広域のピークをリセット。

### 通信・受信診断（0.5.1）

下部のRは受信Rフレーム/秒（掃引回数ではない）。CRC、SEQ欠番、C5+取りこぼし増分、DUP重複、CLIP、G!ゲイン逸脱を区別する。SEQとC5+は重なる可能性があり合算しない。カードの測定注意もUSB CRC / SEQ GAP / C5 DROP / RF取得失敗 / 飽和 / GAIN不一致 / 代替取得 / 欠測へ具体化した。

通信不連続は該当100ms枠を無効にし、健康判定は灰色から有効な10秒窓を取り直す。正常基準のOFF/ON記録中は保存せず失敗にし、以前の基準を保持する。RFの不調や映像品質の低下と同一視しない。しきい値と保存基準形式は変更していない。

### 背景記録

1. ご自身の全VTXをOFFにする。
2. **背景記録 → 全機OFFを確認して記録開始**。
3. 4chを5秒、広域を2MHz刻み137点で1回（約7秒）取得する。表示の選択に関係なく背景は詳細で記録し、完了後は選択していた高速/詳細へ戻る。記録中は全機OFFのまま待つ。
4. 完了したら本体NVSへ保存し、帯域/WFへ復帰する。画面下の **BG SAVED** は現在採用している背景が本体保存済みであることを表す。保存失敗時は **BG RAM** と表示する。

記録中は通常の画面切替を止め、止める操作は **記録中断** として区別する。中断・不正データ・取得失敗は新しい保存背景で上書きしない。変動が大きい背景も拒否する（100ms枠の平均値の最大/最小が中央値から6dB超）。この暫定基準は安定性確認用で、映像が混信するしきい値ではない。常時送信されている信号を、この基準だけでVTXと識別することはできない。

再起動後の保存背景は自動採用しない。アンテナ・位置・方向が同じなら **背景記録 → 設置条件が同じ：保存背景を使う**。4枠の周波数・順序、C5のUSBシリアル、C5ファーム、gain/offset/bw/nodenが一致する場合だけ採用する。アンテナや設置条件が変わったら再記録する。**BG STORED** は保存済み・未採用、**BG NONE** は未取得。

背景の採用/更新では比較履歴・ウォーターフォール・ピーク保持をリセットし、異なる基準の履歴を混ぜない。保存は明示操作時のみで、連続監視のたびにフラッシュへ書き込まない。

## 速度・測定上の境界

通常サーチは各8点群で約25msの整定待ち＋60msの取得。4MHz高速は9組、2MHz詳細は18組。0.3.1実機では高速約0.9–1.0秒/周、詳細約1.8–1.9秒/周。検証した区間と数値はdocs/rf4-0.3.1-verification.mdを参照。背景用の広域取得は120ms＋250msの長い取得を保持する。描画用のグラフ生成は直近約4ms、負荷はログで計測できる。ウォーターフォールは新しい行/表示条件が変わったときだけ再描画する。

2MHz/4MHzは走査ステップであり、その周波数分解能を意味しない。高速の背景差は保存済み2MHz背景の同じ周波数の点と比較する。WFは各測定点の隣との中間まで同じ濃淡で表示し、未測定の中間周波数へ値を補間して取得値として扱わない。C5は約10MHz幅の窓で帯域電力を測る。山の広がりには受信窓とアナログFM信号自体の幅が含まれ、周波数方向のスムージングやスプラインは加えていない。現在の広域表示はFFTではない。瞬間的な電波がその周波数の取得期間外に出ると見逃す可能性があり、連続全帯域監視や電波の占有率の測定ではない。

E2とE1を選んだ場合、その20MHz間隔ではC5自身のイメージ応答が問題になり得る。E2の像がE1に見える場合があり、別送信機やIMDと即断しない。受信強度だけから映像品質・C/I・SNR・送信mW・人物・故障を判定しない。校正と切り分けの理論は[設計書](docs/analog-four-channel-design.md)。

## ビルドと構成

ESP-IDF 5.4.2のPowerShellで `./build.ps1`。書き込み対象を確認してから `./build.ps1 -Flash -Port COMx`。

- SDK: ESP-IDF 5.4.2。別PCのセットアップは../../docs/development.md。
- LVGL 9.2.2、USB Host CDC-ACM 2.0.6、esp_codec_dev 1.6.2。解決版はdependencies.lock。
- main/main.cpp: USB、状態遷移、NVS、PC操作。rf_core.h: 電力集計・背景検証・履歴・候補計算。ui.cpp: 日本語UIと実測データの描画。
- フォントは公式Google FontsのNoto Sans JPを500ウェイト、必要文字だけ20/24pxへ変換。OFLはmain/fonts/OFL.txt。生成済みCは通常ビルドでそのまま使用できる。再生成はtools/font-build/build_fonts.py、版と入力SHAは同フォルダーのprovenance.json。
- 画像バッファと追加LVGL作業領域はPSRAM。LVGL 9.2の現在のTLSF設定では1プール64KiBが上限のため、追加256KiBを4プールに分割。初期開発時の256KiB一括追加でのassertを修正した。
- 受信と描画は別タスク。CRC不正、RF取得失敗、ゲイン逸脱、ADCクリップ、代替取得を有効サンプルへ混ぜない。ホストの100ms集計時刻を使い、遅れて取得したタイマー値で集計時計を巻き戻さない。
- 固定測定条件: gain 30、offset 10MHz、bw 1、fast scan、noden 256。C5の返答とRレコードの周波数リストを照合してから有効表示へ進める。

### PCからの検証コマンド

Tab5側USB-CのCOMx、115200bps。送信は改行区切り。`RF_CMD accepted` は受け付けであり完了通知ではない。PROFILE_CONFIRMED、BACKGROUND_COMPLETE、状態ログを確認する。

```
rf status
rf ui
rf monitor
rf search
rf search 4
rf search 2
rf background YES
rf bg-use YES
rf bg-clear YES
rf peak-reset
rf plan 0 0
rf channels
rf channel 0 R8
rf channels analog
rf channels race
rf dump normal
rf dump quality
rf normal off 3 YES
rf normal on 3 YES
rf normal use 3 YES
rf normal cancel
rf dump background
rf dump sweep
rf dump history
```

`rf search`は現在の選択で走査、`rf search 4`は高速、`rf search 2`は詳細。切替はキュー受付後に反映するため、直後のstatusは旧設定の場合がある。sweep dumpは現在の刻みの実測点だけを出力し、先頭にstep_mhzとpointsを付ける。

`rf normal off/on/use`の番号は枠0–3。offは全機OFF、onは対象1台だけON、useは同じ機体・設置・出力の確認を意味する。offがawait-onへ進んだことを確認してからonを送る。保存完了はNORMAL_COMPLETE、状態はrf dump normalで確認する。

`rf channel 0 R8`は枠0をR8へ変更（枠番号0–3）。`rf channels`は現在の4枠の名前・MHzを表示。`rf channels analog`はE2/E1/F3/F5、`rf channels race`はR2/R3/R4/R5。`rf plan`は最初が枠番号0–3、後ろが0=予定OFF/1=ON。背景操作のYESは設置条件/全機OFFの確認を意味する。接続待ちで古くなった確認操作は再実行しない。dumpの欠測値は-32768、時刻は本体起動後のホスト時刻でUTCではない。
