# Tab5 C5 RF Monitor

Purpose: Tab5 USB Hostで既存C5MKを読み、選択した4chの受信、正常基準とレベル/安定性の評価、背景保存、履歴と広域/WFを表示する。動作確認済み旧版は移管元PCに保持し、リポジトリには含めない。現行0.6.1の仕様と実機証跡はREADME.md、../../docs/jet-waterfalls.mdと../../docs/handoff.md。

- main/: アプリ、測定集計、USBデコーダー、UI。components/: 固定したM5Stack BSP。由来と変更点はREADME.md。
- 受信と描画を分離する。通信不連続は後続フレームの集計前に該当枠・正常基準記録・評価窓へ伝達し、保存済み基準を消さない。CRC不正、RF失敗、クリップ、ゲイン逸脱、欠測、切断を正常値へ置換しない。receiver dBをdBm/送信出力/混信率/映像品質と表記しない。
- 背景の記録・採用は明示操作で行い、C5個体と測定条件を照合する。更新時は別基準の表示履歴を混ぜない。詳細条件はREADME。
- 変更後はbuild.ps1でビルド。コア変更はtools/host_self_test.cppのPC試験も実行する。デコーダー/集計変更は起動時試験と実C5受信、状態遷移/保存変更は実操作を確認。ログの正常動作と物理画面/VTX応答を分けて報告する。
- USB VID:PIDだけではC5とP4を区別できない。書き込み前にチップ型番・シリアル・バックアップを確認する。
- SDKと元C5MKのRF処理はこの表示アプリの通常変更対象ではない。必要な変更には根拠と検証範囲をREADMEへ記す。
- 正常基準は背景と別に周波数別保存。判定は受信状態の暫定評価で、灰色の未判定を保つ。条件・しきい値・既存VTXとの分離限界はdocs/signal-health.md。起動時回帰試験は専用16KiBタスクで実行し、assertとスタック保護を維持する。
