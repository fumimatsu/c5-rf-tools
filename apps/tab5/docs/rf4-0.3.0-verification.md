# 0.3.0 実機検証記録

対象: Tab5 ESP32-P4 rev1.3、USB serial <TAB5_SERIAL>、COMx。C5: <C5_SERIAL>、公式1.2.5+xiaoc5。アプリだけを0x10000へ更新。元16MBバックアップと0.1.0/0.2.0を保持。

## 確認できたこと

- build-0.3.0-fast.log: ビルド成功。flash-0.3.0-fast.log: 書き込み時のハッシュ照合成功。
- 起動時試験: 4ch/8chデコード、分割フレーム、破損CRC、周波数照合、線形電力平均、無効flags、背景のCRC相当チェックサム・個体照合、背景の変動拒否、実時刻の欠落、古い時刻の無視、モード変更時の古い警告消去、IMD候補。
- boot-0.3.0-pools.log: 実C5のcount=4、gain=30、offset=10、bw=1、noden=256を確認し、全4chの有効マスクf、CRC/gaps/drops=0。
- ユーザーが物理4ch画面と履歴グラフを確認。その後、色付きchマーカーとウォーターフォールを目視確認。
- rf4-background-first.log: 4ch 50枠と広域137点の取得・本体NVS保存・4ch復帰。ただしこの背景はF3送信が混ざったとユーザーから申告があり、採用を取り消した。計測の成功と基準の妥当性は分ける。
- rf4-background-retake.log: 全機OFFの再確認後に取り直し、revision=2、4ch基準[-250,-266,-262,-262] centi-dBを保存。137点すべて有効、広域背景7.037秒。4chへの復帰を確認。
- boot-0.3.0-final.log / boot-0.3.0-fast.log: 再起動後にrevision 2を検証し、未採用で読み込み。設置条件を保った状態で明示的に採用し、active=1・stored=1・saved=1を確認。自動採用ではない。
- rf4-fast-benchmark.json: 137点の通常走査9周がすべて有効。1.812–1.923秒、中央値1.888秒。旧7.1秒から短縮。
- グラフ生成の計測例: 約3.8ms、初期観測の最大約16.5ms。これはアプリのグラフ生成時間で、LCD転送を含む全フレーム時間ではない。
- 画面内の背景保存操作については、目視の復帰報告だけで保存完了と扱わず、保存番号/完了ログも確認する。2026-11-13、ユーザーのタッチ操作による背景記録後、WFとBG SAVEDへの復帰を確認。続けてシリアルで新しいrevision 3の保存・採用を確認した。

## まだ検証できていないこと

- 最終版の各4chそれぞれについての、単独送信・同時送信・距離/出力/受信入力の比較試験。
- dBm絶対校正、I/Q補正、映像の復調品質、C/I、SNR、IMDの発生元や送信者の特定。
- 長時間運用や、多数回の再起動・抜き差し、他のTab5パネル型番。
- 通常高速走査の間隙に出る短い信号の全捕捉。ピーク保持も取得期間外の信号を復元しない。

## 開発中に修正した不具合

- LVGL追加メモリを256KiBで一括登録すると、現設定のTLSF上限64KiBによりassert。4つの64KiBプールへ分割した。SDKの検査を無効化していない。
- UIと受信の集計で、ロック前に読んだ古い時刻が集計を巻き戻す可能性があった。expire_binは同じ/古い時刻を無視し、回帰試験を追加。
- 背景記録中の通常画面切替を中断扱いにする導線が分かりにくかった。記録中は通常切替を無効にし、明示的な記録中断ボタンへ変更。
- 表示のみの目視確認と、NVSへの保存完了の確認を分離して記録する。
