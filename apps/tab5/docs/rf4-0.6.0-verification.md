# Tab5 0.6.0: 縦画面と明るさ

2026-11-15。Tab5専用。Pyramid 0.2.2とC5MKのファームは変更しない。

## 変更

- LCD本来の720×1280で配置。4chは2×2と60秒履歴、帯域はスペクトラムと縦長WF。チャンネル、背景、正常基準のダイアログも縦用に再配置。
- `main.cpp` の `bsp_display_start_with_config()` で `sw_rotate=false`、`ui.cpp` は `LV_DISPLAY_ROTATION_0`。BSPのLCD先行→C5給電の順番を維持。
- 描画キャンバスは幅608、履歴224高・帯域168高・WF300高、RGB565合計841,472バイト。旧851,200バイトとほぼ同じ。WFは最大24掃引のまま、原フレームと集計方法は変更しない。
- 画面の「明るさ」で5〜100%、±5%、6段階のプリセット。BSPのバックライトPWMを変更。失敗時は表示値を更新しない。範囲外はPWMを呼ばず拒否。
- 明るさはNVSへ書かず、毎回10%で起動。現在の給電では高輝度で落ちるというユーザー申告に基づく。高輝度での再起動ループを避け、屋外では給電条件に合わせて調整できる。
- 診断 `rf ui` に解像度・回転・明るさを追加。`rf brightness` は現在値とPWMのduty/周波数の読み戻し、`rf brightness <5..100>` は変更。`persisted=0` を表示。`rf backlight-pins` は同梱BSPのGPIO22の出力経路確認用。

## PCで確認済み

- ESP-IDF 5.4.2 / ESP32-P4ビルド成功。最終アプリ1,154,816バイト、既存factory領域に収まる。パーティション表は更新前と一致。
- C++17のコア/デコーダー回帰試験成功。通信不連続・正常基準の保持など0.5.1の試験を継続。
- `tools/ui_smoke` で実際のUIコードとフォントを描画。全画面/ダイアログの表示境界、ナビゲーション、ch選択、明るさの5/100%制限と失敗時保持を確認。生成した4ch、帯域、背景、正常基準、ch選択、明るさの画像を目視確認。
- この試験は合成値によるソフト描画。RF受信・LCD・物理タッチ・高輝度の実機証拠ではない。

## 実機

書き込み前にESP32-P4とUSBシリアルを照合。16MiB全体をローカルへバックアップし、0.5.1のアプリ記述子とNVSを確認。最初の全読み出しは途中でUSB転送が止まったため破棄し、460800で再取得した完全なバックアップを使用した。

`0x10000` のアプリだけを書き込み、esptoolのハッシュ一致と0.6.0起動、起動時全回帰試験成功、`screen=720x1280 rotation=0`、起動時明るさ10%、`sw_rotate=0` を確認。既存チャンネルと保存背景は保持、未採用のまま。

更新前0.5.1の時点でもC5はUSB接続/切断を反復し、受信0だった。0.6.0起動後にも同じ状態を確認したが、ユーザーのC5抜き差し後に復帰。高速4MHz・69点のWFで約963フレーム/秒、完了24掃引の表示を確認。観測時の累計46,656受信フレームではCRC/seq欠番/C5 drops/重複/クリップ/ゲイン逸脱は0。切断の根本原因は特定していない。一度のNVS照合後の再起動では起動から約5.4秒で受信へ復帰したが、最終再書き込み・再起動後は接続/切断の反復が続いた。**再起動後はC5の抜き差しが必要になる場合があり、再接続の安定性は未解決。**

ユーザーが縦画面の表示を確認。シリアル操作で明るさ5→10%のPWM適用成功、0/101%の拒否と値保持、再起動時10%への復帰を確認。NVSは更新前と24,576バイト全て一致し、保存正常基準1件も未採用のまま読み込めた。背景を取り直したり採用したりしていない。

ユーザーが4ch/帯域画面のタッチ切替と明るさダイアログの操作を確認。初回は暗いUIで5↔10%の見た目の差を確認できなかったため、比較用の白い帯を追加して再書き込みした。GPIO22の出力経路はLEDC channel1、周波数5kHz、読み戻したdutyは5%で204/4095、10%で409/4095。白い帯を見た5↔10%の明るさ変化をユーザーが確認した。数値/API成功だけを光量の実測とは扱わない。

10%より上の実機設定、高輝度・屋外視認性、速度改善量、VTX応答の再検証、完全な電源抜き差しは未確認。0.5.1でのF3応答は過去の別条件の証拠であり、この版の受信試験と混同しない。

バックライト配線の参照: [M5Stack公式Tab5回路図](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1132/Tab5_Schematics_PDF.pdf)のGPIO22→バックライト制御。同梱BSPの既存5kHz/12bit設定を維持し、SDK/BSPの制御方式は変更していない。入力%はPWM設定値であり、測定した光量の%ではない。

## 戻し方

1. 対象Tab5のESP32-P4とシリアルを再照合し、今回のローカル全バックアップを指定する。他のCOMデバイスへ書かない。
2. バックアップの `0x10000` から既存factoryパーティションサイズ `0x177000` 分を取り出す。アプリ記述子が0.5.1であることを確認。
3. `esptool --chip esp32p4 --port <確認済みポート> write_flash --flash_mode dio --flash_size 16MB --flash_freq 80m 0x10000 <取り出した旧アプリ>`。NVS/ブートローダー/パーティション表は書かない。
4. 0.5.1と横画面、現在の保存ch・背景・正常基準を確認する。全フラッシュ復元は今回の通常ロールバックには不要。
