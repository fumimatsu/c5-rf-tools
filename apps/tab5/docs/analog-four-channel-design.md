# Tab5 / C5 アナログ4ch監視：校正・理論・画面設計

作成日: 2026-11-12。対象はユーザー指定のアナログ5.8GHz映像。E2=5685 / E1=5705 / F3=5780 / F5=5820 MHz、この順で表示する。

目的は、会場で送信予定にないRFや普段と異なる受信状態に気づき、切り分けの次の操作を選べるようにすること。電波の所有者・故障機・映像品質をRSSIだけで断定する機器にはしない。

本書は事前設計と理論の記録。続く0.3.0で、4ch監視、背景の本体保存、履歴、実測の広域/WFを実装した。ユーザーの追記により初期画面は帯域/WF、配色は直角・白灰を基調にchだけ4色へ変更した。最新の操作と検証はREADME.mdとrf4-0.3.0-verification.mdを参照。I/Q FFT・映像復調・単独VTX比較の専用保存画面・絶対dBm校正は未実装。HTML画面案は模擬データで、実機の表示や受信の証拠ではない。

## 1. 先に押さえる結論

1. 現地の変化を調べる用途には、まず背景記録と1台ずつの比較測定が必要。dBmを表示するための絶対校正は別工程で、今の受信値に定数を足すだけでは成立しない。
2. 「復調」と「相互変調」は別。前者は映像を取り出す操作、後者は非線形回路で新しい周波数成分が生まれる現象。
3. E2とE1は20MHz間隔。C5の既定LO配置では、E2のイメージがE1の測定帯域に重なる。これは別のVTXがE1で送信しているように見える原因になり得る。
4. 4つの中心周波数だけでは、その間や外側にあるRFを網羅して探せない。「4ch監視」と「広域サーチ」の両方を設ける。
5. 表示は「受信上昇」「送信予定なし」「測定飽和」「原因未特定」とする。「混信率」「映像品質」「不良VTX」「犯人」は、この測定だけでは表示根拠がない。

## 2. 現在のC5が実際に送るもの

調査元: `upstream FPVGateC5MK checkout`、HEAD `ea58ae945b7e643145fab149b24b53105b7fc26a`。調査中はソースを変更していない。既存のweb/index.htmlのローカル変更と引き継ぎファイルは保持した。

| データ | 実装上の意味 | 画面で使えること / 限界 |
|---|---|---|
| Rフレーム rawCdb / filtCdb | 約10MHz幅の窓で求めたI/Q帯域電力をdB化。基準はLSB² | チャンネル付近の受信変化。校正済みdBmではない。VTXの全占有帯域の総電力とも限らない |
| filtCdb | 直近3点の中央値＋EMA | 読みやすい数値・バー。短いWi-Fi様バーストや単発上昇が消える場合があるため、異常監視はこれだけに依存しない |
| 各チャンネルのtUs / gain / clips / flags | 実取得時刻、ゲイン、飽和・失敗・ゲイン逸脱・代替取得 | 測定の有効性と比較条件の確認。flagsがないことはRFフロントエンドの完全な線形性の証明ではない |
| ヘッダーseq / count / drops / cycleUs / settingsChanged | 通信・走査状態 | 欠落表示、データ年齢、設定変更後の基準無効化 |

根拠: `multipilot/src/frame.h:24–60`、`meter.h:6–29`、`meter.cpp`、`docs/RADIO_INTERNALS.md` §5, §9、`multipilot/src/main.cpp` のcmdCapture。

I/Qは符号付き10bit I/Q、80MS/s。FFTの周波数軸は反転しており、RF=LO−f_baseband。8192サンプルの最長単発取得でも102.4µs。連続映像を復調したり、フルフレームの同期・SNRを安定測定する機能とは違う。単一取得で見られる有用な帯域は上流ベンチで概ねLO±20MHzと報告され、±40MHz全域を平坦な測定帯域として使わない。

## 3. 似て見える現象を分ける

| 現象 | 起きること | C5で分かること | 次の切り分け |
|---|---|---|---|
| 同一周波数・隣接周波数の干渉 | 不要信号が目的信号の帯域・受信フィルターへ入る | 合計の受信レベルや帯域形状の変化。目的信号と妨害を単純に分離できない | 予定送信をOFFにして残るか、1台ずつON、実際の映像受信機でも確認 |
| 相互変調 IMD | アンプ・ミキサーなどの非線形性で別の周波数成分が生まれる | 計算候補の場所に山があるか。ただし発生場所は分からない | 送信機A/Bを単独→同時にする、受信入力を減衰、別受信機で照合 |
| 受信機内のイメージ | I/Q振幅・位相不整合などでLO対称位置に像が出る | LOを変えたとき、実RF位置と像の動きが異なるか | LO配置を変えて再取得。単独VTXで同時に他chへどう写るか記録 |
| 強入力・ブロッキング | 近くの強い電波で増幅段が圧縮、またはADCが飽和 | ADC clips / gain movedは手掛かり。ただし非飽和でも前段の歪みはあり得る | ゲインや受信入力を下げる、距離を変えて再測定 |
| 反射・マルチパス | 同じ信号の経路差・位相差で強め合う / 打ち消し合う | 位置・アンテナ向きで受信値が変化すること | 同じ場所と向きを固定して比較。別地点でも測定 |
| FMの捕捉効果 | 強い方が復調を支配し、切り替わりやノイズが出る場合がある | 帯域電力だけでは映像の良否を保証できない | アナログ受信機の復調映像、同期・ノイズ等の別測定 |

異なる周波数の電波が線形な空間で重なるだけで、必ず新しい電波が生まれるわけではない。線形・独立な成分の平均電力は加算される。相互変調には非線形性が必要。反射による強め合いと相互変調は別現象。

高調波は2f、3fなどで、5.8GHz信号の2次なら約11.6GHzに現れ、現在のC5監視範囲では確認できない。一方、2fa−fb型の相互変調は元の5.8GHz付近へ戻ってくることがあり、今回はこちらが重要。復調は元の映像情報を取り出す処理で、これらの不要成分とは別の言葉。

相互変調は送信機側、受信機側、接触不良などの非線形接合でも起こり得る。したがって「別の山が出た→そのVTXが悪い」という結論にはしない。

受信機内の3次歪みを調べる正式な2トーン試験では、圧縮していない領域で両入力を1dB変えるとIM3が約3dB変わることを利用できる。外から来た本物のRF成分は、受信入力前の減衰器に対して通常は基本波と同じ1dB/dBで減る。ただし、C5のgain indexを1変えることを1dBの既知入力減衰とみなさない。測定条件・発生段・ノイズ床の確認なしに、この傾きだけで原因を断定しない。

## 4. E2/E1で特に重要なイメージ

現行既定値は `offsetMhz=10`、LO=測定周波数−10MHz。

- E1の測定: LO=5705−10=5695MHz。
- E2の実信号5685MHzをLOの反対側へ写すと、2×5695−5685=5705MHz。
- つまり、E2の像がちょうどE1の測定中心に入る。

上流 `docs/RF_RESEARCH.md:138–169` はgain 30で約18dBのイメージ抑圧を報告している。これはその測定条件・個体の結果で、現在のXIAOの保証値や補正定数ではない。18dBを無条件に引いた「補正済みE1」は実装しない。

LOをE1より高くするとこの特定の像は避けられるが、全ch共通でoffsetを反転すると、今度はE1の像がE2へ入る配置になり得る。現在のC5 USB設定は全ch共通offsetなので、「offsetを一度変えれば両ch解決」としない。まずは別LOでの診断取得を比較する。ch別のLOやデジタルI/Q補正が必要になれば、C5側変更として別途検証する。

単独VTX試験は4×4の応答表を作る。行=ONにした実機、列=測定ch、各セル=全機OFF基準からの受信変化。E2だけONの行でE1も上がるかを最優先で確認する。表は画像や映像内容、出力、距離で変わり得るため、万能な混信除去行列として逆算しない。

## 5. 指定4chの相互変調候補

2波の3次成分は2fa−fb。3波ではfa+fb−fcも調べる。候補中心周波数を計算すると、今回の4中心への完全一致はなく、最近接でも20MHz。ただしFMは幅を持ち、歪み成分の帯域も広がり得るため、中心が一致しないことは無干渉の保証ではない。

5645–5917MHz内の計算候補は次のとおり。実際の発生・強度は未測定。

| MHz | 原因候補となる組み合わせ |
|---:|---|
| 5645 | E2+F3−F5 |
| 5665 | 2E2−E1 / E1+F3−F5 |
| 5725 | 2E1−E2 / E2+F5−F3 |
| 5740 | 2F3−F5 |
| 5745 | E1+F5−F3 |
| 5760 | E2+F3−E1 |
| 5800 | E2+F5−E1 / E1+F3−E2 |
| 5840 | E1+F5−E2 |
| 5855 | 2F3−E1 |
| 5860 | 2F5−F3 |
| 5875 | 2F3−E2 |
| 5895 | F3+F5−E1 |
| 5915 | F3+F5−E2 |

画面では「IMD計算候補」として破線マーカーにする。測定スペクトラムの山、既知VTXの正常範囲、受信機のイメージ候補と違う記号で表示する。候補との一致だけで「IMD検出」にはしない。

## 6. 校正・基準作りの3段階

| 段階 | 実施内容 | 必要性 / 得られるもの |
|---|---|---|
| A 現地の背景記録 | 予定している全VTXをOFF、同じ位置・向き・アンテナ・ゲインで5–10秒。ch別の分布と広域背景を保存 | 最初の運用に必要。「基準より上がった」が分かる。無電波環境や絶対ノイズフロアの校正とは違う |
| B 1台ずつの比較測定 | 同じ条件でE2→E1→F3→F5を単独ON、4ch全部と広域を記録。最後にペア / 全台ON | 4ch版で特に重要。正常時の帯域、隣接への写り込み、組み合わせ時だけ出る変化を把握 |
| C 入力端の絶対校正 | 校正されたRF源＋既知の減衰・ケーブル損失で、複数周波数・入力レベル・ゲインを測定。直線範囲と不確かさも確認 | dBmや他測定器との数値比較が必要になった段階。今の異常に気づく用途の開始条件にはしない |

背景記録には混信源が元から含まれることがある。基準差が小さくても無干渉とは言わない。背景スペクトラムそのものも見られるようにし、基準取得時の受信上昇や飽和を隠さない。送信を止められない会場では「背景未確認」と表示する。

アンテナ・設置場所・方向・ゲイン・LO設定・bw・取得サンプル数・ファームが変わったら基準を無効化する。通常の受信に合わせて背景を自動追従させると不要信号を正常として学習してしまうので、初版は明示操作でのみ取得する。

Cでは高出力VTXを直結して校正する手順にしない。入力端で既知の低レベルを作り、受信経路の直線性を確認する。アンテナ受信値に一つ定数を足して送信mWやEIRPへ換算しない。CWで校正した約10MHz窓の電力と、広いFM信号の総電力も分ける。

## 7. 数値と警告の定義

- 数値の主表示は `基準比 +x.x dB`、詳細に元の `receiver dB`。基準がなければ基準比は `未取得`。
- 基準との差は同じ測定条件の比。希望信号対妨害比C/I、SNR、映像品質、送信出力ではない。
- 電力の集計・合成・差し引きはP=10^(dB/10)の線形値で行う。dBの差を線形差分電力と呼ばない。背景差引きは安定した非相関成分を仮定するため、初版では検出根拠に使わない。
- 100ms枠にrawの有効サンプルの線形平均、最大値、飽和/失敗数を残し、60秒の履歴を描く。平滑表示とは別に短い上昇を保持する。異常を消す中央値だけの監視にはしない。
- しきい値は暫定的な受信上昇検出用。例: 基準の上側分布＋余裕と基準中央値＋6dBの大きい方、直近5枠中3枠で注意、解除に2dBのヒステリシス。実会場で偽陽性/見逃しを評価し、物理的な混信限界や映像劣化の保証値として固定しない。
- 「上昇が観測された枠の割合」を出す場合は分母を有効観測枠とし、未観測時間と観測カバー率も併記する。「電波の占有率」「混信%」としない。初版の主画面には割合を置かない。
- 一般のチャンネルカードは「受信あり / 基準付近 / 背景未取得」。ユーザーが送信予定OFFにしたchに受信上昇があれば「送信予定なし・要確認」。E1ではE2写り込みの注意を添える。
- clips、ゲイン逸脱、欠落、古い値、広域サーチによる中断は、それぞれ測定注意・無効・未観測として表示する。無効時の棒や線を有効な低値に戻さない。
- 誰の送信かは、chと担当の登録、OFF/ON照合で絞る。C5の帯域電力には所有者IDがない。単一センサーで人物や方位を特定しない。

## 8. Tab5の画面構成

### 4ch監視（事前案。0.3.0では「4ch履歴」の別画面）

上段: E2 / E1 / F3 / F5の4カード。中心周波数、受信値、基準比、ピーク、送信予定ON/OFF、測定状態。色だけに依存しない。

中央: 共通の時間軸で60秒の4色履歴。単位は基準比dB、共通の縦軸。rawの短い上昇を残す枠統計と、必要なら別の平滑線。欠落は線をつながない。

下段: 「送信予定なしで上昇」「複数ch同時に上昇」「測定器側の飽和」「E2→E1写り込み要確認」の直近イベント。警告の数を競わせず、次の操作を示す。4chの外側は未観測であることを小さく常時表示する。

操作: 背景記録、単独VTX記録、広域サーチ、記録の保存。実装では日本語の必要文字を含むフォントを用意し、1280×720でタッチ操作を検証する。

### 広域サーチ（0.3.0の初期画面「帯域 / WF」）

上: 5645–5917MHzを走査した周波数対受信レベル。現在・背景・ピーク保持、既知VTXの単独記録、IMD計算候補を重ねる。

下: 周波数×取得時刻のウォーターフォール。短時間だけ出た山、帯域全体の上昇、固定した不要信号の違いを見る。

最初は既存C5の周波数リストを最大8点ずつ切り替える粗走査を利用できる。2MHzステップでも受信窓は約10MHzなので「2MHz分解能FFT」と表記しない。実際の掃引時間・dwell・抜け・最終更新を表示する。4点だけを線で結んだものを広域スペクトラムとして見せない。

単一C5なので広域走査中は4chの連続監視が途切れる。「4ch監視一時停止」と表示し、戻ると元の4ch設定を確認してからLIVEへ戻す。時間を圧縮して間断なく監視していたように描かない。

詳細段階でCフレームからFFTを計算する。DC近傍、帯域端、像の扱い、窓/正規化、LO間の振幅補正、フレーム欠落、取得IDとチャンクの重複/欠損を検証してから採用する。サンプルレート上の±40MHz表示を、そのまま使用可能な±40MHz測定帯域としない。

### 操作できる画面案

同梱の `analog-four-channel-preview.html` は模擬データ。通常4台、予定のないchの上昇、4ch外の山、E2→E1の像、2波同時時の山、測定飽和を切り替えて表示を検討する。実機の校正値や検出性能を示すものではない。

ブラウザの画面案は、6シーン×2モード、送信予定ON/OFF、IMD候補の切替を確認。1280px幅で両モードを720px高以内に収め、320px幅でも横方向のはみ出しがないことを確認した。これはHTMLの画面案の検証であり、Tab5のLVGL描画・実受信・検出性能の検証ではない。

## 9. 実装の順序と受け入れ条件

1. 4ch実受信: `pilots 5685,5705,5780,5820`、count=4・周波数一致を確認。現行Tab5のis_racebandは8ch専用なのでプロファイル照合へ変更する。gain / bw / offsetなどは設定と照合して記録し、gainの実値を未取得のまま「固定条件で比較済み」としない。
2. 履歴と背景: 未取得/取得失敗/条件変更/切断を含む状態管理、時刻と欠落の可視化、4ch別のraw/平滑/ピーク。
3. 単独試験: E2だけON時のE1応答、各ch単独とペア、距離/ゲインを変えた再現性。直線範囲が足りなければ「相互変調検出」の実装より受信入力条件の改善を優先する。
4. 広域走査: 周波数群を切り替え、4ch監視を中断/復帰。全機OFFで残るRF、単独VTXの帯域、短い信号の見逃しを調べる。更新速度は測ってから記載する。
5. I/Q詳細・必要な校正: 実RFとLO像の分離、C5側と別受信機の照合。実際の映像劣化との照合なしに混信度や品質点へ変換しない。

ビルド、起動時デコーダー試験、実C5のcount=4/周波数/flags、物理画面、各VTXのON/OFF、背景無効化、切断/復帰、起動順序、広域からの4ch復帰を分けて確認する。設計だけを検証済みとは扱わない。0.2.0の確認はR1–R8表示とR8 ON/OFF。0.3.0の実受信・背景保存・表示・速度等は別の実機検証記録に分ける。

## 10. 資料と実装の差

上流 `docs/INTEGRATION_GUIDE.md:141–145` はaccepted 5180–5917MHz、Web `multipilot/web/c5mk-link.js:27` も同じ制限。一方、CLI実装 `multipilot/src/main.cpp:35` のkMinMhz/kMaxMhzは5100–5950MHz。文書/既存UIの運用範囲とCLIの入力許容範囲は一致しない。広いCLI範囲を検証済み測定性能として使わない。今回の4chと提案した5645–5917MHzは双方の範囲内。

現行Tab5の数値がdBmではないという既存の境界は維持する。追加するのは、その根拠と基準/校正の段階・測定器由来の誤認対策。新しい購入、規制適合判定、他プロジェクトへの変更は含めない。

## 0.3.0の実装時に確認した事項

- ユーザーのF3送信が最初の背景記録に重なり、F3の背景が+4.80 dB、他chが約−2.7 dBになった。F3の低い差分はこの基準の影響だった。全機OFFを再確認して記録したrevision 2は[−2.50,−2.66,−2.62,−2.62] dB。背景の取り直しで改善した。
- 通常サーチの待ち/取得を25ms/60msに短縮。実測9周の中央値1.888秒、範囲1.812–1.923秒。背景取得用の広域は120ms/250msを維持し、約7秒。
- 描画は周波数方向の平滑化をしない。白い測定点と接続線を区別する。広い山は受信窓とFM信号幅を含む結果で、点を細かく描くことは狭いRBWやFFTへの変更ではない。
- サーチの既定表示は受信値で、背景も重ねる。背景差への切替を用意し、基準に含まれるRFを差分表示だけで見えなくしない。
- 背景の100ms集計は古いタイマー値で時刻を巻き戻さない。受信コールバックと処理タスクの時刻境界の競合に対する試験を追加した。
- 4ch連続監視から広域へ切り替えるときは、警告の過去の投票状態を消去し、復帰後の新しい観測で判定する。
