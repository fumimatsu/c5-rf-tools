# 正常基準・レベル・安定性（0.5.1）

目的: ユーザー指定の「弱くて影響を受けやすそうな受信」「平均は十分でも落ち込む受信」を見つける。帯域の発散判定、VTX故障判定、混信率、SNR、映像品質は扱わない。単独の正常基準と比較する受信状態の目安。

## 記録

各周波数について全VTX OFFを30個の100ms完全枠、対象の正常な1台だけONを100枠記録する。先頭の部分枠は捨てる。途中で無効RF flags・ゲイン逸脱・クリップ・欠測・タイムアウト・切断があれば不採用。ONへ進む操作は人が対象1台だけONを確認して行う。2秒以上古い確認操作は実行しない。await-onの待ち時間は操作者が必要とする時間を保ち、明示中断できる。

100ms枠内では既存のraw線形電力平均を使う。各枠の平均から中央値・百分位を求める。dBの算術平均を受信電力平均として使わない。

記録受入は以下の暫定条件。映像受信の正常規格ではない。

- ON中央値 − OFF P95 >= 10dB。
- ON P90 − P10 <= 3dB。
- ON中央値 − 最低の100ms平均 <= 6dB。

失敗時は新しい基準を保存・採用しない。以前の保存値は保持し、理由を画面へ表示する。OFF/ONの誤操作で同程度の値を取った場合も、上昇不足で拒否する。

0.5.1ではCRC不正・不正フレーム長・R形式不正・seq欠番・C5 drops増加・重複・カウンター再同期・C5時刻逆行も伝達する。パーサーは後続の有効フレームを処理する前にエラーを通知し、該当100ms枠を不完全とする。同じUSB受信塊に有効値が残っていても正常な枠へ戻さない。正常基準のOFF/ON記録中は専用の通信エラーで失敗にし、以前の保存基準を保持する。

## 評価

4ch監視で、対象が予定ON・固有周波数・有効な受信・条件一致の基準を明示採用している場合だけ評価する。100個の連続した有効な100ms枠を必要とし、欠測や無効値で窓をリセットする。通信エラーも全chの窓をリセットし、直近1秒は通信欠落、その後は評価待ちを表示する。RF無効サンプルは該当chの窓をリセットする。WF・背景/正常基準記録中・予定OFF・同周波数の重複枠・未採用/不一致は灰色。

レベルの現在値は直近10枠（約1秒）の中央値。

- 正常比低下 = 正常基準中央値 − 現在値。
- 無送信比上昇 = 現在値 − OFF P95。信号対雑音比ではない。
- 正常比低下 >= 12dB、または無送信比上昇 < 6dBで赤。
- 正常比低下 >= 6dB、または無送信比上昇 < 10dBで黄。
- それ以外は緑（基準内）。強いだけでは異常としない。

安定性は直近100枠（約10秒）。

- 変動幅 = P90 − P10。
- 黄の変動幅しきい値 = max(3dB, 正常時変動幅 + 2dB)。
- 赤の変動幅しきい値 = max(6dB, 正常時変動幅 + 4dB)。
- 落ち込み = その10秒の中央値からmax(6dB, 正常時中央値−正常時P10+3dB)を超えて低い枠。
- 1回以上の落ち込みで黄、3回以上または5枠以上の連続低下で赤。回数は連続する低い枠を1回として数える。
- 変動幅と落ち込みの悪い方を採用。悪化は即時、改善は10回連続の判定（約1秒）を確認し、保持中は「復帰確認」。無効化は保持せず即座に灰色。

一定して弱い受信はレベル赤・安定性緑になり得る。オンオフ直後は安定性も注意になり、直近10秒から変化が抜けて復帰確認を終えると安定性は戻る。100ms未満の低下は平均化され得るため検出を保証しない。時間は既存のホスト受信時刻で、RF上の正確な事象時間ではない。

## 保存と状態

NVS namespace rf4、key normal<周波数>（例normal5917）。版1・サイズ・周波数・C5シリアル・ファーム・gain/offset/bw/noden・OFF中央値/P95・ON中央値/P10/P90/最低値・FNVチェックサムを持つ。各明示記録完了時だけ保存。読み込みは有効な個体/設定との一致を確認し、起動後は未採用。位置/機体/アンテナ/出力の一致は自動検出できないため操作者が確認する。

同じRF周波数のR7/F8は同じキー。機体IDを電波から復元しない。同じ周波数に複数機がある場合の分離は行わない。元の背景キーとチャンネル設定キーは別で、正常基準の記録で上書きしない。NVSを全消去するfallbackは追加しない。

GUIは各枠の正常基準ボタンから開始。記録中はチャンネル・モード・背景変更を止め、明示中断を提供する。失敗と未記録を緑へ置換しない。波形や数値は従来の受信値で、健康判定の理由には「正常比」「無送信比」「変動」「低下回数」を区別して表示する。

## 限界

基準と測定対象の距離・向き・アンテナ・出力・機体が変われば、原因がVTXでなくても受信は変わる。他機や外来RFが同じ測定窓へ入ると合計電力が上がり、目的信号の低下を隠す場合がある。約10MHzの窓の受信電力を測るもので、VTX全占有帯域の総電力や受信映像の品質を測っていない。緑は無干渉の保証ではない。

## コードと検証

main/signal_health.h: 独立した記録・統計・判定。main/signal_health_self_test.h: 境界と回復・欠測の試験。main/rf_core.h: 有効な100ms枠と判定の接続。main/main.cpp: NVS/状態遷移/CLI。main/ui.cpp: 4chカードと記録UI。

既存と追加の起動時試験を専用16KiBタスクで実行してから本体を起動する。追加試験のローカル変数が従来のmainタスクへ収まらなかったため分離した。保護・assertは無効化していない。移管時点で独立した0.5.0検証書は存在しない。0.5.1のPC/実機起動時試験・受信・NVS保持の結果は[0.5.1検証書](rf4-0.5.1-verification.md)。
